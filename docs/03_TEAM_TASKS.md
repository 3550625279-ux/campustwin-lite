# 三人任务书

成员姓名和 GitHub 用户名尚未填写；A/B/C 是责任角色，不代表已完成分配。共同文件不等于无人负责：A 维护构建与调度，C 维护结果记录，公共协议变更由三人评审。

## A：校园环境、场景与薄调度层

| 顺序 | 要做什么 | 交付证据 |
| --- | --- | --- |
| A1 | 解析地点、道路、设施 CSV；校验重复 ID、非法参数、悬空引用 | 合法样例可加载；非法文件报字段和文件行号 |
| A2 | 封装图结构，查询最短路线；处理同点和不可达 | T1→食堂 120 m；不可达返回 `reachable=false` |
| A3 | 通过编辑场景副本与 `replace_scenario` 完成增删改，再保存/重载 | 独立 `demo_a` 能演示一次真实编辑和重载 |
| A4 | 按接口文档实现薄调度器，接入 A/B/C 和记录器 | 联合验收通过；调度器没有排队或学生决策逻辑 |
| A5 | 统一 CLI/菜单；核心 MVP 后实现账号及权限 | 参数错误有可理解提示；课程功能独立验收 |

维护目录：`src/environment/`、`src/simulation/`、`app/`、`examples/demo_a.cpp` 及对应头文件。共同修改根 `CMakeLists.txt` 前在 PR 中注明。

难点：图与文件的一致性、删除引用的处理、公共集成工作量。删除被道路/设施/学生引用的地点时首版拒绝操作并报告依赖，不静默删除下游数据；学生引用在运行初始化时再次校验。

## B：学生、日程、行为和移动

| 顺序 | 要做什么 | 交付证据 |
| --- | --- | --- |
| B1 | 解析学生 CSV；验证 ID、速度、时间、地点和目标设施 | 20 人数据正确加载；无效速度被拒绝 |
| B2 | 按 `ceil(距离/速度)` 计算移动，更新到达时刻 | 两教学楼分别在 t=2/t=3 到达 |
| B3 | 到达食堂产生唯一请求，区分排队和服务 | 同一学生不会重复到达；缺少完成事件不会继续吃饭 |
| B4 | 处理开始/完成事件，就餐后返回宿舍 | 最后两人在 t=29 结束；迟到或错设施事件报错 |
| B5 | 输出每分钟学生快照，提供独立演示 | `demo_b` 使用假资源接收器验证闭环，日志清楚 |

维护目录：`src/students/`、`examples/demo_b.cpp`、学生测试和学生输入；不维护 C 的窗口状态。

难点：状态机和时序。首版午餐链不可中断，后续活动只在就餐结束后开始，不强行在固定时刻打断排队或服务；完整课程冲突留到后续迭代。

## C：设施服务、统计和输出

| 顺序 | 要做什么 | 交付证据 |
| --- | --- | --- |
| C1 | 读取设施配置，建立一个 FIFO 队列和多个窗口 | 不依赖 B，用固定到达序列可运行 |
| C2 | 按阶段释放窗口、入队、分配窗口，发两类反馈 | 旧排队者优先；同分钟新到者不会抢队 |
| C3 | 防重复请求、重复完成和超窗口服务 | 非法事件不改变有效队列；边界测试通过 |
| C4 | 维护等待、完成、忙碌时间和队列指标 | 20 人样例总等待 170、平均 8.5、最大队列 18 |
| C5 | 实现四份 CSV 的记录器，保证稳定格式 | `check_mvp_outputs.py` 通过；重复运行文件一致 |

维护目录：`src/resources/`、`src/reporting/`、`examples/demo_c.cpp`、服务测试和到达序列。

难点：同一时刻事件顺序、统计的分母和窗口占用区间。C 的核心不选择学生下一站，不替 B 修改位置。

## 公共任务和交接

| 工作 | 主维护 | 共同责任 |
| --- | --- | --- |
| 接口和字段冻结 | A 整理变更 | 三人确认语义和可实现性 |
| 输入基准 | A 场景 / B 学生 / C 服务序列 | 三者校验器通过 |
| 第一次闭环 | A 发起联调 PR | B/C 同时修复各自模块问题 |
| 输出核验 | C 导出 / B 核学生状态 | 三人对手算样例 |
| 周记与答辩材料 | 各自 | 写实际完成的提交和实验结果 |

每个任务的 PR 必须带：改动目的、运行命令、输入、实际输出、剩余限制。不得只交一份无法接入公共工程的私有项目压缩包。

第一轮不要求 A 一人处理所有合并冲突和业务问题。调度只负责暴露问题；错误属于哪个状态所有者，就由其维护人修复。
