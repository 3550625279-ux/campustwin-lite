# 公共接口契约 v0.1（待团队确认）

唯一编译基线是 `include/campustwin/contracts.hpp`；本文件规定含义和调用前后条件。修改头文件必须同步本文件、数据格式和验收工具，经三人评审后合并。当前状态是可审阅草案，尚未宣称团队已冻结。

## 单位、ID 与初始化

| 项 | 约定 |
| --- | --- |
| 时间 | `SimTime`，非负整数分钟；12:00=t=0；不使用系统时钟或 `sleep` 推进 |
| 距离、速度 | `double`；米、米/分钟；有限且严格为正 |
| 运行长度 | `duration_minutes >= 1`；遍历 0…duration，含最后一个快照 |
| ID | 非空 ASCII 字母/数字/下划线/短横线；区分大小写；不靠名称识别业务对象 |
| 请求 ID | MVP 为 `学生ID:lunch:1`；在一次运行中全局唯一 |
| 窗口 ID | 设施内从 0 开始；分配时选择编号最小的空闲窗口 |
| 容量 | 地点静态容量 > 0；首版不作为人数准入限制 |

场景中的道路为无向边；每对端点只保留一条边，不接受反向重复、自环和非正距离。设施 ID 与地点 ID 不同，例如 `F_CANTEEN` 位于 `L_CANTEEN`；首版一个地点最多一个服务设施，设施必须位于食堂。学生起点和就餐后地点均不同于食堂位置，确保两次出行距离正。

所有输入在仿真开始前验证。运行期间场景不可编辑。学生、设施都由 `reset` 清空之前运行状态，不共享跨运行队列或累计统计。输入规模须检查容器大小、数值解析和时间加法溢出，不能让非法负数经无符号转换成为大正数。

## A：`ICampusEnvironment` / `IRouteProvider`

| 方法 | 输入 → 输出 | 约定 |
| --- | --- | --- |
| `load_directory` | 场景目录 → 内部有效场景 | 读取三份 CSV；先完整解析校验，再替换；失败保留原有效场景 |
| `save_directory` | 输出目录 → 三份 CSV | 只保存静态场景；写文件失败报错，不宣称成功 |
| `replace_scenario` | 场景值 → 内部有效场景 | UI 可编辑场景副本后一次提交；非法编辑不污染原场景 |
| `scenario` | 无 → `const CampusScenario&` | 运行期间引用保持有效；B/C 不修改 |
| `find_route` | 起终点 ID → `RouteInfo` | 有效 ID、不可达返回 false/空 path；未知 ID 抛验证错误 |

`from==to` 返回可达、距离 0、路径只有该地点。其余可达路径的距离是最短总距离；同距路线可选任一条，但同一输入必须稳定。B 只根据总距离计算时间，不在首版按每一条路逐段模拟。

## B：`IStudentEngine`

| 方法 | 负责的事情 | 调用限制 |
| --- | --- | --- |
| `reset(scenario, population)` | 校验引用、创建学生、置为 AtLocation | 每次运行一次，不推进时钟 |
| `tick(now, routes)` | 更新就餐到期、移动到达与日程出发；返回本分钟到达请求 | t=0 起连续调用，每分钟一次 |
| `on_service_started(event)` | Queued→InService | 请求、学生、设施与当前等待状态必须一致 |
| `on_service_completed(event)` | InService→Eating，设置就餐结束时刻 | 请求必须正在接受服务，完成时刻必须有效 |
| `snapshots(now)` | 返回值对象，不修改状态 | 每分钟阶段末调用，按 student_id 排序 |

出行耗时为 `ceil(distance_m / walk_m_per_min)`，正距离至少 1 分钟；校验后将结果转为 `SimTime`。食堂到达时，B 先置 `Queued` 再返回 `StudentArrival`；不能提前猜测等待或完成时刻。

服务完成时刻 t 进入 Eating，就餐区间为 `[t,t+meal_minutes)`；届时开始去后续地点，最终到达设为 Finished。`tick` 内先处理到期活动/移动，再处理可启动日程，避免同一活动重复触发。MVP 不处理中断午餐链的冲突课程。

B 当前实现遵守下文调度顺序：开始通知必须在 `tick(t)` 后且 `event.at==t`；完成通知必须在 `tick(t)` 前且 `event.at==t`，允许同分钟多条完成通知。完成事件的窗口须与开始事件相同，完成时刻须等于开始时刻加设施服务时长；缺失通知时学生保留原状态，不由 B 自动完成服务。开始事件中的等待时长须等于开始时刻减到达时刻。

`snapshots(t)` 只读取已经执行过的当前 tick；收到下一分钟完成通知后、尚未执行该分钟 tick 前，拒绝读取上一分钟快照，以免把未来状态标成过去。非法单条反馈不修改学生状态。`reset` 失败保留原运行，`tick` 遇到无效路线或时间溢出时不提交半批更新，可修正路线后重试同一 tick。路线可达性在实际启动相应行程时检查，因为 `reset` 不接收路线提供者。实现与独立测试见 [B 模块说明](11_B_STUDENT_MVP.md)。

## C：`IFacilityEngine`

| 方法 | 负责的事情 | 不能顺手做的事 |
| --- | --- | --- |
| `reset(facilities)` | 建立窗口、队列、请求状态和计数 | 不能伪造学生到达 |
| `complete_due(now)` | 累计上一分钟忙碌窗口时间；完成到期服务并释放窗口 | 此时不从队列补人 |
| `enqueue(arrivals, now)` | 校验本批事件并入队 | 不开始服务，不修改 B |
| `start_ready(now)` | 为所有空闲窗口按规则取人，返回 ServiceStarted；分配完后更新最大队列指标 | 不立即完成正时长服务 |
| `snapshots(now)` | 返回阶段末快照 | 不能因读取而继续推进服务 |
| `summaries(now)` | 返回累计原始计数与观察时长 | 不丢弃截止时刻尚未完成的请求 |

每个 t 严格按 `complete_due → enqueue → start_ready → snapshots` 调用，包含空批次。`complete_due(0)` 不累计前一段时间；后续 t 累计区间 `[t-1,t)` 的忙碌窗口数。服务从 t 开始，占用 `[t,t+service_minutes)`，在 t+service_minutes 的完成阶段释放。

到达事件必须 `event.at==now`。同分钟到达先按 `student_id` 排序；此前等待的人始终排在新到者前面。分配顺序为设施 ID、窗口 ID 升序。完成事件按设施 ID、窗口 ID 排序。重复请求、未知设施、同一学生已有未完成请求均是验证错误；先校验整批到达再修改队列，避免一半成功一半失败。

## 调度器的唯一顺序

| 阶段 | 操作 | 完成后的状态 |
| --- | --- | --- |
| 1 | `C.complete_due(t)`，逐条通知 `B.on_service_completed` | 到期窗口释放，学生开始就餐 |
| 2 | `B.tick(t,A)` | 到期就餐者出发；移动者到达；生成到达事件 |
| 3 | `C.enqueue(arrivals,t)` | 新到者接在旧队尾 |
| 4 | `C.start_ready(t)`，逐条通知 `B.on_service_started` | 空闲窗口被分配，学生状态同步 |
| 5 | 读取 B/C 快照，交给记录器 | 记录本分钟全部动作后的稳定状态 |

这是固定步长调度，不是离散事件跳时；首版不混用两套模型。所有阶段都必须处理 t=0 和最后一分钟。正服务/就餐/移动时长避免同分钟无限自触发。

## 输出与错误

`IRunWriter` 接收只读值对象。`begin` 创建或检查输出目录，已有四个目标文件时首版拒绝覆盖，提示换一个输出目录；`write_tick` 按完成、到达、开始的顺序写事件，快照按 ID 排序；`finish` 写汇总并检查流状态。

若中途发生错误，程序返回非零并明确提示本次输出不完整；不要把已有的半份文件当成功结果。文件打开/读写失败可以抛 `std::runtime_error` 或其派生；配置、状态和事件不合法抛 `ValidationError`。入口统一捕获并显示上下文，禁止吞错后继续用默认 0 数据运行。

`scenario()` 引用只用于运行期读取；事件和快照按值返回，不跨模块保留可变容器指针。没有模块可以持有并修改别人的学生、窗口或队列对象。

## 统计口径

| 指标 | 明确定义 |
| --- | --- |
| `queue_length` | 阶段 4 分配完成后仍在等待的人数，不含在服务和就餐者 |
| `max_queue_length` | 各分钟阶段末 queue_length 的最大值；不统计入队到分配之间的临时容器峰值 |
| `in_service` | 阶段末正在占窗口的请求数 |
| `arrived / started / completed` | 本次运行截至当前的累计请求数 |
| `total_wait_minutes` | 对所有已开始服务者累计 `start_at-arrival_at` |
| 平均等待 | total_wait / started；started=0 时输出 0。是已开始者口径，截止时刻仍在排队者不进入分母 |
| `busy_window_minutes` | 在 `[0,now)` 内每个窗口忙碌时间之和，单位窗口·分钟 |
| 利用率 | busy_window_minutes / (window_count × observation_minutes)，输出 0…1；观察时长 0 时输出 0 |

最后一分钟仍排队/服务的学生保留原状态；时间截止不等于全部完成。汇总必须同时显示到达、开始、完成数，避免只报告已服务者的均值而掩盖积压。
