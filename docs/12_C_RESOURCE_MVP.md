# C：资源队列与结果记录

C 维护食堂队列、窗口、服务事件和四份结果文件。它不负责决定学生去哪，也不修改 B 的学生对象；调度器把 C 产生的服务事件反馈给 B。

## 独立演示

在仓库根目录构建后运行：

```bash
./build/demo_c --facilities data/fixtures/resource_facilities.csv --arrivals data/fixtures/resource_arrivals.csv --duration 6
```

终端显示事件 CSV、每分钟队列与窗口状态，以及最终等待、最大队列和利用率。事件写到标准输出，状态及汇总写到标准错误，因此重定向标准输出可得到单独的事件 CSV。程序不会读取手算结果文件。对比 `data/fixtures/resource_expected_events.csv`：S001 和 S002 同时到达，S001 先服务；t=2 S001 完成、S003 到达，原队列中的 S002 仍然先于 S003；t=6 S003 完成。`--help` 查看默认参数。输入格式见 [数据格式](05_DATA_FORMAT.md)。

## 运行规则

每分钟依次调用 `complete_due`、`enqueue`、`start_ready`、`snapshots`。完成阶段释放已到期窗口；到达阶段先完整校验这一批，同一分钟按学号排序接在旧队列之后；开始阶段将队首分配给编号最小的空闲窗口。非法批次不会只入队一部分。请求 ID 必须与学生一致，例如 S001 的请求为 `S001:lunch:1`。

服务占用 `[开始时刻, 完成时刻)`，忙碌窗口分钟只统计已经经过的区间。最大队列是分配窗口后每分钟队列长度的最大值。运行截止时仍在等待或服务的请求保留在快照和统计中。

`CsvRunWriter` 按事件、学生快照、设施快照和汇总输出四份 CSV。记录每个 tick 前先检查并组装本分钟数据；若输入不合法，可修正后重试，已经验证的事件不会因为这类失败被重复写入。打开、写入或关闭文件失败仍可能留下不完整结果，需要换目录重跑。

## 验证

`resource_engine_behavior` 覆盖 FIFO、同分钟排序、窗口分配、拒绝重复与错配请求、批次校验失败不改变队列、时间溢出和截止统计。`reporting_behavior` 覆盖错误输入后重试、最后 tick 与防覆盖。`integrated_mvp` 使用真实 A/B/C，逐条核对 20 人、120 分钟结果，并检查窗口数、路程和截止时刻变化。

设施窗口数限制为 1…100000；A 和 C 使用同一个上限，避免场景能保存却无法运行。该公共契约变更需要团队在合并时共同审阅。
